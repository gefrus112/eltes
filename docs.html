Overview

Eltes is a browser-based AI agent workspace. It gives you a fast chat interface, a model switcher that works mid-conversation, agent-style tool steps and a history you own. There is no Eltes account and no Eltes server: the app is static files, and requests go from your tab directly to whichever model provider you connect.

Three ideas, in order

  • Bring your own key. Paste a provider key into Settings. It is stored in this browser's local storage and attached to requests at request time.
  • One conversation, many models. The transcript is shared. Only the reply header changes when you switch.
  • Local by default. Chats, preferences and keys live in localStorage. Clearing site data removes them for good.
Demo mode. With no key connected, Eltes answers from a small local script so the interface is fully explorable. Demo replies are labelled and never claim to be a live model.

Quickstart

Sixty seconds from a blank tab to a live answer.

Open the workspace

Eltes runs entirely client-side. Open app.html — no install, no sign-in. It works from a local file server or any static host.

Pick a starting model

Use the picker in the top bar, or press ⌘M. Claude Sonnet 4.5 is a good default; Gemini 2.5 Flash is the fastest.

Add one provider key

Settings → API keys, paste a key, press Save. The status chip flips to Connected and the demo pill disappears when that model's provider is available.

Send a message

Type, press Enter, watch tokens arrive. Use the stop button at any time — partial answers are kept.

terminal — run Eltes locally 
# clone the repository
git clone https://github.com/gefrus112/eltes
cd eltes

# any static server works; no build step
python3 -m http.server 4173

# then open http://localhost:4173
No key handy? Open app.html?sample=1 to load a ready-made conversation, then try the command palette with ⌘K.

API keys

Keys are read from localStorage when a request is made and sent as the Authorization header (OpenAI-compatible) or x-api-key (Anthropic). They are never bundled into exports and never posted anywhere except the provider's own endpoint.

What a request looks like

Eltes builds the smallest request the provider accepts: a system message, the last 24 turns of the conversation and stream: true. Nothing is proxied.

request shape — OpenAI-compatible 
POST https://api.openai.com/v1/chat/completions
Authorization: Bearer sk-proj-…
Content-Type: application/json

{
  "model": "gpt-4.1",
  "stream": true,
  "messages": [
    { "role": "system", "content": "You are Eltes…" },
    { "role": "user", "content": "Hello" }
  ]
}

Custom endpoints

Any OpenAI-compatible base URL works: Ollama, vLLM, LiteLLM, LM Studio, a corporate gateway. Add the base URL, a model ID and an optional token under Settings → API keys → Custom endpoint.

local Ollama 
# base URL
http://localhost:11434/v1

# model id
llama3.1

# key — leave empty for local models
Browser CORS applies. A provider must allow requests from your origin. OpenAI, Anthropic, Google, Groq and OpenRouter do. Self-hosted servers may need --allow-origins or a proxy. If a request fails instantly with “Could not reach…”, CORS is usually the cause.
Shared machine? Keys sit in plain local storage. Remove them in Settings before handing over the browser, and keep eltes-backup.json files private — exports intentionally leave keys out.

Per-chat models

A chat remembers the model it was last using. The default model in Settings applies to new chats only, so an old thread does not silently change brains when you return to it.

Agent mode

Toggle Agent in the composer (or in Settings → General) to see the work behind an answer as a sequence of tool steps rather than a wall of text:

agent run — step log 
read    src/auth/session.ts        312 lines
grep    "refreshToken"             6 matches
edit    src/auth/session.ts        +18 −4
test    pnpm test session          12 passed

Each step is rendered inside the assistant message and collapses naturally into the transcript. Steps are simulated in demo mode; with a connected key the run streams the model's answer in real time.

Attach a text file with the paperclip to inline it into the prompt as a fenced block. Files are read in the browser and never uploaded anywhere except to the provider you ask.

Design rules Eltes follows

  • Visible, not magical. Tools appear with their arguments and result counts, not as "done".
  • Interruptible. Stop keeps every token received so far and cancels the request.
  • No silent writes. Erasing the active run is explicit; retrying a reply truncates the branch you can see.
Attach context, not code execution. Use the paperclip (or drop a file on the composer) to inline a text file into your prompt. Workspace-wide tools, MCP connectors and sandboxed execution are next — no code is executed in your browser today.

History & export

Every conversation is written to localStorage on change, debounced by 120 ms. When there is no active chat the welcome screen appears; existing threads are grouped by Today, Yesterday, Previous 7 days and so on.

KeyContents
eltes.chats.v1Array of chats: id, title, model, messages, timestamps, pinned flag.
eltes.settings.v1Keys, default model, favourites, streaming, density and motion preferences.
eltes.active.v1The id of the conversation you were last reading.

Renaming, pinning, branching

Hover a conversation in the sidebar for pin and menu actions. The menu supports rename, clear, export and delete. Editing one of your own prompts truncates the thread at that point so the next reply is generated from the edited text.

Exports

Use the download icon in the top bar or ⌘K → Export conversation. Markdown is for sharing; JSON is for backups. Settings → Data exports every chat at once, and importing a backup restores chats without overwriting your existing keys.

Local means local. There is no recovery, no sync and no server copy. Clearing site data, using private mode, or switching browsers starts you from zero. Export before you clean up.

Self-hosting

Eltes is plain HTML, CSS and JavaScript. There is nothing to compile and no environment variables to configure. Serve the directory from any static host — GitHub Pages, Netlify, Vercel, S3, nginx or a laptop.

production static server 
# nginx — minimal config
server {
  listen 80;
  root /var/www/eltes;
  index index.html;

  # optional: keep the docs and app in the same place
  location / { try_files $uri $uri/ /index.html; }
}

Structure

  • index.html — landing page.
  • app.html — the workspace.
  • docs.html — this page.
  • assets/js — icons, model catalogue, app engine and site scripts.
  • assets/css — theme tokens, landing, app and docs styles.
Want a private deployment? Host the files behind your SSO, put a proxy in front of the provider APIs and point the custom endpoint at the proxy. No Eltes infrastructure is involved.

Privacy

The honest version: your prompts travel directly to the model provider you selected and are governed by that provider's terms. Eltes itself has no server to receive them.

What Eltes stores

  • Locally: chats, titles, settings, favourites and API keys — all in localStorage.
  • Nowhere else: no analytics, no error reporting, no feature flags, no fonts fetched from a CDN. Fonts are bundled.
  • In exports: chats and settings only. Keys are deliberately excluded.

What providers see

A short system prompt, the recent conversation and your key. Eltes does not add telemetry headers or identifiers. Review each provider's retention policy; several offer zero-retention modes for API traffic.

Threat model, plainly. Anyone with access to your unlocked browser profile can read local storage. Use a dedicated browser profile for keys you care about, and rotate anything you paste into a shared machine.

FAQ

Do I need an account or a subscription?

No. Eltes has no accounts. You only need an API key from a provider you already use, and you pay that provider directly for tokens.

Are my API keys safe in local storage?

They are as safe as your browser profile. They are never sent to Eltes, never included in exports, and are masked in the interface. On a shared machine, remove them when you finish. A dedicated browser profile is the pragmatic answer.

Why does a request fail instantly?

Usually CORS or an invalid key. A 401/403 means the provider rejected the credential; “Could not reach…” in under a second means the browser blocked the request before it left. Check the network panel, the key, and whether the provider allows direct browser calls.

Does it work offline?

The interface and demo mode work offline once loaded. Live model replies require a network connection to the provider. A service worker is not included yet — if you host the files locally they never need re-downloading.

Can I run local models?

Yes. Start Ollama (or any OpenAI-compatible server) with CORS enabled and point Settings → Custom endpoint at it, for example http://localhost:11434/v1 with model llama3.1.

What exactly does demo mode do?

It streams a locally generated reply from a small set of intents — code, auth, model comparison, SQL, debugging, copywriting — and labels the result. Nothing is sent anywhere and no request is charged to anyone.

Is this affiliated with OpenAI, Anthropic or Google?

No. Eltes is an independent interface. Model names and provider marks are used descriptively and remain the property of their owners.

How do I move my chats to another computer?

Settings → Data → Download, then Import on the other machine. Keys are not transferred, so add them again there.
