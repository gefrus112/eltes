Overview

Eltes is a browser-based AI workspace. Add a provider API key, pick a model, and Eltes streams that provider's answer, renders tool calls, and keeps history in this browser. Optional Supabase Auth accounts provide a real sign-in; passwords are never stored by Eltes. Direct mode calls providers from the browser; an optional separately hosted Vercel/local proxy can test keys and forward requests. If a hosted provider is not connected, the app says so instead of inventing an answer — and Eltes CAI, a small on-device helper, is available with no key.

Three ideas, in order

  1. Local-first. Chats, settings and provider keys live in this browser. Supabase stores account credentials and the small Eltes profile; sign-in tokens use HttpOnly, SameSite cookies, with the Secure flag on HTTPS, not localStorage.
  2. Bring your own key. By default, requests go from your tab to the provider. An optional trusted backend can relay a key for each request without persisting or logging it in the function code.
  3. Real agent loop. When tools are on, the model can call calculate, current_time and search_history; every call is shown as a card with its arguments, result and runtime.
  4. On-device when you need it. Eltes CAI-1 answers chat, Eltes questions, model choice, arithmetic, units and dates in this tab. No key, no network, and it is explicit about what it does not know.

Quickstart

From a blank tab to a live answer, with one provider key.

Open the workspace

Go to app.html. A Supabase account is optional; Eltes CAI and local chats work without signing in. Install the PWA optionally for a standalone app window. A first-run Quick setup guide offers local CAI, provider-key connection, and install guidance; reopen it with ⌘K → Quick setup.

Connect a provider

Press Connect a provider, choose a provider, and save its API key. Or open Settings → API keys. Provider API keys are separate from your Supabase Eltes account. The pill in the top bar turns green when at least one key is present. No key yet? Pick Eltes CAI-1.

Pick a model

Use the model button or ⌘M. Models without a key show a needs key badge; star the ones you use most and they move to the top.

Send a message

Type and press Enter. Tokens stream in as they arrive; press the stop button to keep a partial answer. Metrics appear under the reply when it finishes.

terminal — run Eltes locally 
# clone the repository
git clone https://github.com/gefrus112/eltes
cd eltes

# any static server works; there is no build step
python3 -m http.server 4173

# open http://localhost:4173
No key handy? Eltes CAI-1 runs in this tab with no key. For an open-weight model, run Ollama and point Eltes at http://localhost:11434/v1 under Custom endpoints.

Accounts

Eltes uses Supabase Auth for real email/password accounts. Supabase manages the credential; Eltes never writes your password or a fake profile to browser storage. Display names are saved in the public.eltes_profiles table, with row-level security restricting reads and changes to that profile’s authenticated user ID.

Create or sign in

Open Create account, choose a display name, email and password of at least 12 characters, then sign in. If email confirmation is enabled for the Supabase project, follow its confirmation email first. Existing Eltes local-only profiles are not credentials and are removed; create a new Supabase account. Chats, settings and BYOK provider keys remain in this browser and are not uploaded by account sign-in.

Where accounts work

  • Vercel deployment: deploy Eltes and its /api/auth function on the same origin. The API sets Secure, HttpOnly, SameSite cookies for the access and refresh tokens.
  • Local development: run npm start and open the local Eltes page. The local server exposes the same account API.
  • GitHub Pages: static Pages cannot run /api/auth; account sign-in will report that the backend is unavailable. The local workspace and CAI continue to work.

The API uses only Supabase’s public publishable key and the signed-in user token. It does not use a service-role key. Account-changing requests are same-origin checked. Browser sessions are not stored in localStorage; sign-out asks the server to revoke and clear the cookie. This improves credential handling, but does not make an account impossible to compromise: use a unique password and protect your device.

API keys

Keys are read from localStorage at request time and are excluded from exports. In direct mode, OpenAI-compatible providers receive Authorization: Bearer …; Anthropic receives x-api-key and anthropic-version. With the optional proxy, the browser sends the key in a request header to the configured backend, which forwards it using the provider's required authentication. Eltes function code does not persist or log it; the key still transits the backend platform.

Rotating and removing keys

  • Keys can be replaced at any time under Settings → API keys; saving overwrites the old value immediately.
  • Removing a key disables that provider's models until a new one is saved.
  • Exports never include keys. Backups are safe to share; localStorage is not.
Least privilege. Use a dedicated key per device, set a spend limit at the provider, and revoke it from the provider dashboard if a machine is shared.

Custom endpoints

Anything that speaks OpenAI's /chat/completions can back Eltes: Ollama, vLLM, LiteLLM, LM Studio, a Cloudflare Worker or your team gateway. Set a base URL, a model id and — only if your server requires one — a token.

  1. Open Settings → API keys → Custom endpoint.
  2. Enter the base URL, including /v1 when that is what your server expects.
  3. Enter the model id exactly as the server reports it.
  4. Pick Custom endpoint from the model picker and send a message.
Ollama — OpenAI-compatible 
# 1. run a model
ollama run llama3.1

# 2. in Eltes → Settings → Custom endpoint
Base URL   http://localhost:11434/v1
Model id   llama3.1

# Ollama allows browser origins from localhost by default.
# For another device, set OLLAMA_ORIGINS to your static host.
OLLAMA_ORIGINS="https://eltes.example" ollama serve

When CORS blocks the browser

Configure the optional Vercel backend described in Self-hosting, or run Eltes with npm start for the local API during development. The proxy forwards the user's key for that request and only allows fixed provider targets. Do not paste a provider key into a source file, public static host, or shared deployment environment variable.

HTTPS pages cannot call HTTP endpoints. If Eltes is served over HTTPS, a plain http://localhost endpoint will be blocked by mixed-content rules. Serve Eltes locally for local models, or expose the model over HTTPS.

Eltes CAI — our own models

CAI (conversational agent intelligence) is a deterministic JavaScript rules-and-knowledge system implemented in assets/js/cai.js, not a trained neural network. It runs inside the tab with no key and no network. It can still make mistakes, so treat its scope and fallback as limits—not a guarantee of correctness.

ModelStrengthExample
Eltes CAI-1Bounded on-device chat, calculator and simple equation solving“Which model for code?” or “solve x² − 5x + 6 = 0”
Eltes CAI-1 FastShorter answers, quicker pacing“Convert 68 °F to °C”
Eltes CAI DocsEltes setup, keys, accounts, downloads“How do I connect a DeepSeek key?”

CAI covers Eltes documentation, model recommendations from the catalogue, arithmetic, percentages, common calculator functions (including roots, powers, trigonometry and logs), one-variable linear and quadratic equations, unit and temperature conversion, the current date and time, word counts and a curated glossary of AI terms. Trigonometric inputs use radians. It is not a computer algebra system and cannot solve arbitrary proofs, higher-degree equations or every math problem. For chat understanding, it can retrieve exact matching excerpts and recap user prompts included in the active conversation context; it cannot search every saved chat from this local turn. It has no arbitrary-corpus import or training pipeline. Unsupported or ambiguous questions should receive a fallback, but this is not a guarantee against mistakes.

A tokenizer vocabulary is a set of text pieces, not a count of verified facts. Adding four million words would not by itself teach the assistant meanings or make its answers reliable. Knowledge expansion needs vetted source documents, retrieval with traceable references, abstention when evidence is weak, and regression tests.

Real model streaming, including Claude

Eltes streams from provider APIs when Settings → General → Stream responses is enabled. Claude uses Anthropic’s native Messages API; OpenAI-compatible providers stream chat-completion events. Replies are never simulated for hosted models.

  • Save a valid provider API key in Settings → API keys. Eltes checks locally for a key before sending and opens a connect prompt if it is missing.
  • Claude Sonnet 5.5 uses Anthropic SSE and paints tokens as they arrive. OpenAI-compatible providers use SSE with a live cursor and first-token metrics.
  • 401/403, 429, model-not-found and CORS/network failures have separate retry guidance.
  • Eltes does not include hosted model credits or determine whether a provider account has free quota. CAI is the free, on-device option; hosted usage follows provider terms and billing.

Per-chat models

The model is stored on the conversation, not globally. Switch mid-thread and the next reply uses the new model while the history stays intact. New chats use the default model chosen in Settings → Models. Deep links such as app.html?model=glm-4-6 preselect a model from the landing page.

No silent fallbacks. If a hosted model needs a key, Eltes shows a connect card naming the provider. It does not quietly answer with something else.

Agent & tools

Tools are real function calls, not a scripted animation. Turn on Tools in the composer (or set it as the default in Settings) and a supported model may call one of Eltes’ built-in local tools or tools from connected MCP servers. Eltes executes each call and returns its result to the model, then lets it continue — up to four rounds.

ToolInputWhat it does
calculate{ expression }Evaluates arithmetic in a restricted sandbox — digits and operators only
current_time{ timezone? }Returns the current date and time, optionally in an IANA timezone
search_history{ query }Searches saved conversations locally and returns titles plus snippets
create_file{ filename, content }After you approve the full contents, stores one text file in the chat as a download (up to 100 KiB each; 10 files / 800 KiB per chat)
run_shell{ command }Only when connected to an opt-in local Node runner; each exact command requires browser approval. Commands run with your OS account permissions and are not sandboxed.

What the timeline shows

  • Thinking while the request is open, then streaming once tokens arrive.
  • Tool cards with the tool name, arguments, a running/done state and the runtime in milliseconds.
  • Metrics after the turn: first-token latency, total time, tokens in/out and tokens per second.
  • Model and provider chips on every assistant message, so a long thread with switches stays readable.

Tool calling support

Tools are only offered when the selected model advertises support. Models without tool support — the Eltes CAI family and completion models such as Codestral — are sent the plain conversation. If a provider rejects the tool schema, the error card reports it and retry without tools still works.

Local command execution is disabled by default. On a computer you control, start the Node server with ELTES_ENABLE_SHELL=1 npm start, then connect using its one-time token in the Terminal panel. A hosted model with tool calling can request commands, but every exact command must be approved in the browser first. Commands are unsandboxed and run with your OS account permissions. Output is returned to the model. The runner accepts only loopback/same-origin requests and starts commands in the repository workspace, but this is not a filesystem sandbox; commands can access other paths allowed to your account. Execution is limited to 30 seconds and 32 KiB of output. It is unavailable on GitHub Pages and Vercel. File downloads and MCP calls also require their own approvals.

MCP connections

Eltes can connect the web workspace to remote Model Context Protocol servers that support Streamable HTTP. Select MCP in the top bar, enter the server’s HTTPS endpoint and, if required, a bearer token. The server must allow browser CORS requests from the Eltes origin.

  • Connections and bearer tokens stay in memory in the current tab; they are not saved to chat history or browser storage. Closing or refreshing the tab removes them.
  • Enable only the servers you want offered as tools. MCP tools are available only when Tools is on and the selected model supports tool calls.
  • Eltes asks for approval before every MCP tool call and displays the server, tool, and complete arguments. Declined calls are not sent to the MCP server.
  • Approved arguments and results are sent to both the MCP server and the selected model. Connect only servers you trust; an MCP server can access or modify data in its own environment.

Some servers require authentication or do not support browser access. Eltes does not proxy MCP traffic; contact the server operator if the endpoint rejects browser CORS requests.

Chats & export

Conversations are grouped into Today, Yesterday, Previous 7 days, Previous 30 days and Older. Pinned chats sit on top. Every row has a menu with rename, pin, clear, export and delete. Use Guide in the composer to set per-chat preferences for hosted models; those preferences are saved with that conversation. The on-device CAI helper does not apply free-form instructions. Installing Eltes as a web app does not grant access to your computer. In browsers that support the secure-context folder picker, the Files button opens a folder you explicitly select; only top-level supported text/code files are listed, and adding a file places its contents in the draft for your review before sending. Folder access is memory-only for the current tab; it is not recursive and does not grant access to the rest of the device. If folder picking is unavailable, use Attach to choose individual files. Quick setup has shortcuts to choose files or configure the local runner.

Editing and retrying

  • Edit a user message to rewind the thread to that point and put the text back in the composer.
  • At the start of the composer, press ↑ to browse prompts from this chat; at the end, press ↓ to move forward and restore your draft.
  • Attach text and code files, including PHP and Lua, with the paperclip or drag them onto the composer. Files are read in the browser and inserted into the draft; each file is limited to 400 KB, with 800 KB total per selection. PHP and Lua code fences receive syntax coloring in chat.
  • Retry re-runs the last turn with the current model; the failed turn is kept out of the history.
  • When you scroll away from the newest messages in a long thread, use Latest to jump back to the conversation end.
  • Copy works on replies and on each code block independently.
  • Feedback thumb buttons are stored locally and never uploaded.

Video editor

Eltes Video Editor is a lightweight, browser-native tool for quick cuts. Open the video editor from the workspace tab or this link. Choose a local video file, drop it onto the preview, or enter a direct HTTP(S) media URL.

Make a quick edit

  1. Load a clip. Choose a local file, drag it onto the preview, or paste a direct HTTP(S) video URL in the editor panel. MP4 with H.264 and WebM are common compatible choices; support for other containers and codecs varies by browser. URL sources must be direct media files, not YouTube/Vimeo pages, and their host must allow CORS and byte-range requests for editing and seeking to work.
  2. Set the trim and pace. Enter start and end times in seconds, scrub to find a moment, and choose playback speed from 0.5× to 2×. The selected range is exported at the chosen speed.
  3. Adjust the look. Choose Original, Cinema, Mono or Warm, then combine brightness, contrast, saturation, sepia, hue shift, soft focus and vignette controls. Presets are starting points and can be adjusted freely.
  4. Add a title or caption. Type up to 120 characters, choose Inter, Georgia or monospace, and set the size, color, vertical position, alignment and backdrop. The overlay appears in the preview and is rendered into the export for the selected trim.
  5. Export. Pick Standard or High quality and select Export video. The browser renders the clip on-device; keep the page open until the download begins.
Browser-side processing. Local files are opened with a temporary browser URL and are not uploaded to Eltes. If you enter a remote URL, your browser requests that host directly; Eltes does not proxy it, and the host can see the request and your network address. Remote previews and canvas exports require CORS. Your original local file is not modified.

An HTTPS-hosted Eltes page may block plain-HTTP video URLs as mixed content; use an HTTPS source. If you use a signed URL, its query string is sent to that host by your browser, so only use URLs and hosts you trust.

Export and compatibility

Export format is selected from formats supported by the current browser, usually WebM and sometimes MP4. The quality menu changes the recording bitrate, not the source resolution; exports are capped at 1920 pixels on the longest side. Audio is carried through when the browser exposes the video's audio track to the recorder. Browser support for canvas capture, audio capture, MediaRecorder and codecs differs, so an export can be silent or unavailable on some browser and codec combinations. If a file will not load or export, try a current Chrome, Edge or Firefox build and a browser-playable MP4 or WebM.

This is a focused single-clip tool, not a multitrack editor: it does not mix audio, add transitions, combine clips or save a project file. Large or high-resolution videos can use substantial memory and processor time. The current edit is kept in the open page; export or record your settings before leaving.

What the launcher does

  1. Changes into its own folder, so it works from any drive or USB stick.
  2. Uses Node.js 18+ for the local API when available; otherwise finds Python and serves static files.
  3. Starts a local server bound to 127.0.0.1 and opens your default browser.
  4. With --shell, prints a one-time pairing token for the opt-in command runner.
  5. Leaves the server running until you close the console window.
It is a text file. Open eltes.bat in Notepad before running it. There is no installer or elevation prompt. The launcher itself makes no outbound connection and binds the local server to localhost; provider requests only happen when you use a hosted model.

For a static preview, Python can serve the files. To use the local API or the supervised terminal runner, use the Node server instead:

The command runner is not a sandbox. Commands run with your OS account permissions, may access files outside the starting folder, and are returned to the chosen model. Approve only commands you understand. Details and limits are in Agent & tools.

Install on a Chromebook

Open the secure Eltes website in ChromeOS Chrome. In the address bar, click the install icon if shown, or use ⋮ → Cast, save, and share → Install page as app. Launch Eltes from the Chromebook Launcher; the manifest supplies standalone display, a dark theme and maskable icons. No APK, Android app, or Linux package is needed. The installed hosted PWA uses the same origin as the website and cannot run Chromebook terminal commands itself.

For local command execution, ChromeOS must have its Linux development environment enabled and Node.js 18+. Start the local Node server from Linux with shell support enabled, then open/install Eltes from that same local origin—not from the hosted PWA. The runner starts new commands under the server user; it does not attach to or read an existing Terminal session. Python commands work only if Python is installed in the same Linux environment; each approved command starts a new process rather than an interactive shell or Python REPL. Every exact command still needs browser approval. ChromeOS port forwarding can vary: the runner intentionally refuses connections the server does not see as loopback. If that happens, do not weaken the guard or expose the runner to a network.

Update by replacing files. Copy a new build over the old folder and keep localStorage. Chats, settings and provider keys stay in the browser; your Supabase account lives remotely and is not in the download.

Self-hosting

Publish with GitHub Pages

The repository’s .github/workflows/pages.yml workflow assembles and deploys only the static site files to GitHub Pages. Subsequent updates publish through the repository workflow. GitHub Pages serves HTML, CSS, JavaScript, images and the Windows download; it does not run the API backend, store secrets, proxy model requests, or grant provider free-tier access.

Without a configured proxy, users save keys in their browser and provider APIs receive requests directly from that browser, subject to provider CORS. Eltes also includes Node-based local API routes for development and separate Vercel functions for deployment.

Run the local site and API

With Node.js 18 or newer, run npm install and npm start, then open http://localhost:4173/app.html. This serves the static site and API routes, including the same-origin /api/auth route for Supabase accounts. The server binds to 0.0.0.0 for development-preview compatibility; it is not intended for public hosting, so keep it on a trusted network. Use HOST=127.0.0.1 npm start to bind only to loopback. A Python static server serves only files, so it does not provide account sign-in, key testing, or proxy routes.

Deploy the optional proxy to Vercel

  1. Import the repository into Vercel with the project root as the root directory. The functions are in api/; vercel.json sets a 60-second function limit.
  2. Set the project environment variable ELTES_ALLOWED_ORIGINS to exact comma-separated browser origins, without paths or trailing slashes. Example: https://gefrus112.github.io,http://localhost:4173.
  3. Deploy, then in Eltes Settings → API keys → Optional Vercel/local backend, enter the Vercel deployment origin and use Save and test.

The available routes are /api/health, /api/key-check, and streaming/non-streaming /api/chat. The backend only contacts fixed provider hosts and allowlisted provider/model pairs; it never accepts an arbitrary upstream URL. CORS origin checks are not authentication; these routes are public to non-browser clients unless you add access controls. Do not offer an unprotected shared proxy to untrusted users without adding authentication and rate limiting. The key transits the backend for each call; the function code does not persist or log it, but the platform and provider process the request. Use only a deployment you trust and set provider spending limits. Static hosting and Vercel backend deployment are separate; this documentation does not mean a deployment has already occurred.

Deployment checklist

  • Serve over HTTPS in production. The clipboard API and some provider endpoints require a secure context.
  • Keep every asset path relative so the app works from a subdirectory.
  • Do not add analytics that read localStorage; it holds keys.
  • If you add a content security policy, allow connect-src for each provider you use.
Sharing with a team? Host the static build, then give each person their own keys. There is no shared key store by design.

Privacy

Eltes includes no analytics, telemetry, or third-party font requests. In direct mode, a model request goes from your browser to the selected provider. If you configure the optional backend, key checks and model requests transit that backend; the function code does not persist or log provider keys, but the backend platform processes request metadata and the key while handling the call.

What providers see

Your prompt, the conversation history sent with it, and whatever tool definitions or results are included in that request. That is exactly what any chat client must send to get an answer. Eltes does not add your Supabase account ID to provider requests.

Deleting data

Use Settings → Data to delete all chats, or Account → Delete profile to remove the profile. Keys can be removed individually. Clearing site data for the origin removes everything at once.

FAQ

Why is there no demo mode?

A simulated answer is indistinguishable from a wrong one. Eltes would rather show a connect card or a typed error than pretend a model replied. If you want to try the interface without a paid provider, run Ollama locally and use a custom endpoint.

Do I need an account?

No. Accounts are optional profiles. The workspace, keys, history and exports work without one. Create a profile only if you want a name and avatar attached.

Is it safe to paste an API key into a web page?

Only on a page you trust and control. Eltes is static and self-hostable, so you can audit every line and serve it yourself. Keys sit in localStorage, which any script on the origin can read — do not load untrusted third-party scripts alongside it.

Why does a provider fail with a network error?

Usually CORS. The provider must allow the browser origin in direct mode. See Providers & CORS, or configure the optional Vercel/local backend in Settings → API keys.

Which models can use tools?

Models with tool support in the catalogue: Claude 5.5 and 4.5, GPT‑6 Sol/Luna, GPT‑4.1, Gemini 2.5, GLM-4.x, DeepSeek V4.1/V4, Grok, Qwen3, Mistral Large, Llama 3.3/4 and most OpenRouter routes. The Eltes CAI models run their own local intents and Codestral is sent the plain conversation.

Can I use it offline?

Yes, partly. Eltes CAI-1 answers chat, Eltes questions, arithmetic, units and dates with no network at all. Hosted models need a connection, unless you point a custom endpoint at a model running on your machine. The Windows launcher serves the whole site locally.

How do Eltes accounts and provider keys work?

Eltes accounts use Supabase Auth email/password sign-in and need the same-origin Vercel or local Node API; static GitHub Pages cannot host sign-in. OpenAI, Anthropic, DeepSeek, and other providers are connected separately with your API keys in the workspace. Those keys stay in this browser and are not your Eltes account password.

Can I install Eltes on a Chromebook?

Yes. Install the secure website as a Chrome PWA from the Downloads section or Chrome's install menu. It appears in the Chromebook Launcher and opens in a standalone window. It is a web app, not an APK; it cannot run shell commands directly. Local command execution requires a separate opt-in Node runner in the ChromeOS Linux environment and per-command browser approval.

What is the Windows .bat file?

eltes.bat is a readable launcher included in eltes-windows.zip. It uses Node.js for the local API when available, otherwise Python for static files, binds to 127.0.0.1:4173, and opens the workspace. It does not install a service or need admin rights. The risky local command runner is disabled unless launched with eltes.bat --shell; Node.js 18+ is required, and each command still needs browser approval.

What happens to my chats if I clear site data?

They are gone. localStorage is the only copy. Export a JSON backup from Settings → Data first if the thread matters.

Ready to connect a real model?

Bring one key. Eltes does the rest — streaming, tools, metrics and history that stays here.
