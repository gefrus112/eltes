Overview

Eltes is a browser-based AI agent workspace. You bring a key for a real model provider; Eltes streams that provider's answer, renders the tool calls, and keeps the history in this browser. There is no Eltes server, no account requirement and no demo mode — if a provider is not connected, the app says so instead of inventing an answer.

Three ideas, in order

  1. Local-first. Chats, settings, keys and profiles live in localStorage. Clearing site data is the nuclear option, and it is yours to press.
  2. Bring your own key. Requests go from your tab to the provider over HTTPS. Eltes never sees or relays them.
  3. Real agent loop. When tools are on, the model can call calculate, current_time and search_history; every call is shown as a card with its arguments, result and runtime.

Quickstart

From a blank tab to a live answer, with one provider key.

Open the workspace

Go to app.html. No install and no sign-in. An account is optional and only adds a profile.

Connect a provider

Press Connect a provider, paste a key, and save. Or open Settings → API keys. The pill in the top bar turns green when at least one key is present.

Pick a model

Use the model button or ⌘M. Models without a key show a needs key badge; star the ones you use most and they move to the top.

Send a message

Type and press Enter. Tokens stream in as they arrive; press the stop button to keep a partial answer. Metrics appear under the reply when it finishes.

terminal — run Eltes locally 
# clone the repository
git clone https://github.com/gefrus112/eltes
cd eltes

# any static server works; there is no build step
python3 -m http.server 4173

# open http://localhost:4173
No key handy? Use a local model instead: run Ollama and point Eltes at http://localhost:11434/v1 under Custom endpoints. It is still a real model, not a demo.

Accounts

An Eltes account is a profile, not a login system. It stores a name, an email, an optional GitHub handle and the provider that created it. There is no password, no session cookie and no email delivery. The profile is written to eltes.account.v1 and shared with the workspace and marketing pages through the eltes:account event.

Create or sign in

Open auth.html. Creating a profile needs a display name and an email; signing in restores the profile already in this browser, or creates one from the email if the browser has none. Because there is no server, neither flow can prove ownership of an email address — treat it as a local label, not a credential.

GitHub

The GitHub button currently links a handle locally. Real OAuth requires a server to hold the client secret and exchange the code — it cannot be done safely in a static page. The button is already wired to switch modes when a backend exists:

auth.html — before the scripts 
<!-- Set this once hosted auth exists -->
<script>
  window.ELTES_CONFIG = {
    authEndpoint: 'https://auth.example.com'
  };
</script>

With authEndpoint set, the button redirects to /github/start?return=…. Your backend completes the OAuth exchange, then returns the user to auth.html with a profile encoded as base64url JSON:

callback shape 
# the client accepts this query parameter
https://eltes.example/auth.html?account=<base64url(profile)>

# profile
{
  "name": "Ada Lovelace",
  "email": "ada@example.com",
  "username": "ada",
  "avatarUrl": "https://avatars.githubusercontent.com/u/1"
}

The page decodes it, writes the local profile, clears the parameter and shows the signed-in state. Avatar URLs are restricted to https:; everything else is stored as text.

Do not put a client secret in this page. Anything shipped to the browser is public. The static build deliberately ships without one and says so in the UI.

API keys

Keys are read from localStorage at request time. OpenAI-compatible providers receive them as Authorization: Bearer …; Anthropic receives x-api-key plus anthropic-version and the direct-browser header. They are excluded from exports and never sent anywhere except the provider endpoint you selected.

Rotating and removing keys

  • Keys can be replaced at any time under Settings → API keys; saving overwrites the old value immediately.
  • Removing a key disables that provider's models until a new one is saved.
  • Exports never include keys. Backups are safe to share; localStorage is not.
Least privilege. Use a dedicated key per device, set a spend limit at the provider, and revoke it from the provider dashboard if a machine is shared.

Why not proxy everything? A proxy would need to hold your key, which defeats the point of BYOK. Eltes only recommends one when the provider blocks browsers, and then it is your proxy, your key.

Custom endpoints

Anything that speaks OpenAI's /chat/completions can back Eltes: Ollama, vLLM, LiteLLM, LM Studio, a Cloudflare Worker or your team gateway. Set a base URL, a model id and — only if your server requires one — a token.

  1. Open Settings → API keys → Custom endpoint.
  2. Enter the base URL, including /v1 when that is what your server expects.
  3. Enter the model id exactly as the server reports it.
  4. Pick Custom endpoint from the model picker and send a message.
Ollama — OpenAI-compatible 
# 1. run a model
ollama run llama3.1

# 2. in Eltes → Settings → Custom endpoint
Base URL   http://localhost:11434/v1
Model id   llama3.1

# Ollama allows browser origins from localhost by default.
# For another device, set OLLAMA_ORIGINS to your static host.
OLLAMA_ORIGINS="https://eltes.example" ollama serve

When CORS blocks the browser

A small proxy that forwards to the provider fixes it without changing the app. Keep the key on the proxy, never in the page, and restrict the origin:

Cloudflare Worker — minimal CORS proxy 
export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    if (url.pathname === '/health') return new Response('ok');

    const upstream = new Request(
      'https://api.deepseek.com/v1/' + url.pathname.replace(/^\/v1\//, ''),
      request
    );
    upstream.headers.set('authorization', `Bearer ${env.PROVIDER_KEY}`);
    upstream.headers.delete('host');

    const res = await fetch(upstream);
    const out = new Response(res.body, res);
    out.headers.set('access-control-allow-origin', 'https://eltes.example');
    return out;
  }
};
HTTPS pages cannot call HTTP endpoints. If Eltes is served over HTTPS, a plain http://localhost endpoint will be blocked by mixed-content rules. Serve Eltes locally for local models, or expose the model over HTTPS.

Per-chat models

The model is stored on the conversation, not globally. Switch mid-thread and the next reply uses the new model while the history stays intact. New chats use the default model chosen in Settings → Models. Deep links such as app.html?model=glm-4-6 preselect a model from the landing page.

No silent fallbacks. If a model needs a key, Eltes shows a connect card naming the provider. It does not quietly answer with something else.

Agent & tools

Tools are real function calls, not a scripted animation. Turn on Tools in the composer (or set it as the default in Settings) and the model may call one of three local tools. Eltes executes the call in the page, returns the result to the model, and lets it continue — up to four rounds.

ToolInputWhat it does
calculate{ expression }Evaluates arithmetic in a restricted sandbox — digits and operators only
current_time{ timezone? }Returns the current date and time, optionally in an IANA timezone
search_history{ query }Searches saved conversations locally and returns titles plus snippets

What the timeline shows

  • Thinking while the request is open, then streaming once tokens arrive.
  • Tool cards with the tool name, arguments, a running/done state and the runtime in milliseconds.
  • Metrics after the turn: first-token latency, total time, tokens in/out and tokens per second.
  • Model and provider chips on every assistant message, so a long thread with switches stays readable.

Tool calling support

Tools are only offered when the selected model advertises support. Reasoning-only models such as DeepSeek R1 and completion models such as Codestral are sent the plain conversation. If a provider rejects the tool schema, the error card reports it and retry without tools still works.

Nothing leaves the page for tools. Arithmetic, time and history search run locally in JavaScript. Only the model request and its tool results go to the provider.

Chats & export

Conversations are grouped into Today, Yesterday, Previous 7 days, Previous 30 days and Older. Pinned chats sit on top. Every row has a menu with rename, pin, clear, export and delete.

Editing and retrying

  • Edit a user message to rewind the thread to that point and put the text back in the composer.
  • Retry re-runs the last turn with the current model; the failed turn is kept out of the history.
  • Copy works on replies and on each code block independently.
  • Feedback thumb buttons are stored locally and never uploaded.

Storage meter

The sidebar footer shows how much of the browser's local storage the app is using. The meter is deliberately conservative: browsers commonly allow about 5 MB per origin, and large attachments or very long threads consume it fastest.

Pricing

Eltes is free to run and brings your own keys, so you pay providers directly at their published rates. There is no markup, no subscription and no card on file. A hosted tier with managed keys is in progress — the pricing section says coming soon because it is not purchasable yet.

Self-hosting

Eltes is a static site. Any host that serves files with the right MIME types works: GitHub Pages, Cloudflare Pages, Netlify, S3, nginx or python3 -m http.server. There is no server-side code to run and no environment variable to set.

Deployment checklist

  • Serve over HTTPS in production. The clipboard API and some provider endpoints require a secure context.
  • Keep every asset path relative so the app works from a subdirectory.
  • Do not add analytics that read localStorage; it holds keys.
  • If you add a content security policy, allow connect-src for each provider you use.
Sharing with a team? Host the static build, then give each person their own keys. There is no shared key store by design.

Privacy

Eltes has no analytics, no telemetry, no fonts fetched from a third party and no backend to receive anything. The only outbound requests are the ones you trigger: a model call to the provider you configured, or a link you click.

What providers see

Your prompt, the conversation history sent with it, and whatever tool definitions or results are included in that request. That is exactly what any chat client must send to get an answer. Eltes adds no account identifier, because it does not have one to add.

Deleting data

Use Settings → Data to delete all chats, or Account → Delete profile to remove the profile. Keys can be removed individually. Clearing site data for the origin removes everything at once.

FAQ

Why is there no demo mode?

A simulated answer is indistinguishable from a wrong one. Eltes would rather show a connect card or a typed error than pretend a model replied. If you want to try the interface without a paid provider, run Ollama locally and use a custom endpoint.

Do I need an account?

No. Accounts are optional profiles. The workspace, keys, history and exports work without one. Create a profile only if you want a name and avatar attached.

Is it safe to paste an API key into a web page?

Only on a page you trust and control. Eltes is static and self-hostable, so you can audit every line and serve it yourself. Keys sit in localStorage, which any script on the origin can read — do not load untrusted third-party scripts alongside it.

Why does a provider fail with a network error?

Usually CORS. The provider must allow the browser origin. See Providers & CORS, or route the request through your own proxy and point a custom endpoint at it.

Which models can use tools?

Models with tool support in the catalogue: Claude 4.x, GPT-4.1 and o4-mini, Gemini 2.5, GLM-4.x, DeepSeek V3, Grok, Qwen3, Mistral Large, Llama 3.3/4 and most OpenRouter routes. DeepSeek R1 and Codestral are sent the plain conversation.

Can I use it offline?

The interface loads locally, but model calls need a network — unless you point a custom endpoint at a model running on your machine.

Does GitHub sign-in really work?

It links a handle locally today. Real OAuth needs a secret-holding backend, which static hosting cannot provide. The client is wired for an authEndpoint so the hosted build can complete the real exchange without a rewrite.

What happens to my chats if I clear site data?

They are gone. localStorage is the only copy. Export a JSON backup from Settings → Data first if the thread matters.

Ready to connect a real model?

Bring one key. Eltes does the rest — streaming, tools, metrics and history that stays here.
